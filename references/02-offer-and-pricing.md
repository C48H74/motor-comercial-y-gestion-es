# 2. Oferta y precio

## 2.1 Anatomía de la oferta

Toda oferta debe cerrar estos seis elementos. La falta de cualquiera = oferta vaga.

| Elemento | Pregunta que responde | Criterio de calidad |
|---|---|---|
| **Resultado** | ¿qué cambia en la vida del cliente? | sustantivo concreto + número cuando exista |
| **Plazo** | ¿en cuánto tiempo? | plazo real, no aspiracional |
| **Mecanismo** | ¿por qué funciona tu forma? | nombre propio para el método (da propiedad) |
| **Prueba** | ¿quién ya obtuvo ese resultado? | nombrado y autorizado |
| **Riesgo** | ¿qué pasa si no funciona? | garantía con exposición calculada (§2.5) |
| **Precio** | ¿cuánto, en qué formato? | anclado a la alternativa, no a tu costo |

### Señales de oferta vaga (reescríbela antes de seguir)
"solución completa" · "transformación digital" · "alianza estratégica" · "aumenta la productividad"
**sin número** · "atendemos empresas de todos los tamaños" · "a medida para ti" sin decir qué cambia.

## 2.2 Los 6 modelos de precio

Evalúa siempre los seis y elige **uno** como principal. Los modelos mixtos están permitidos, pero deben declararse.

| Modelo | Cuándo sirve | Riesgo para ti |
|---|---|---|
| **Por proyecto** (alcance cerrado) | alcance claro, poco cambio | el alcance crece, el margen cae |
| **Por hora / día** | alcance indefinido, consultoría | castiga tu eficiencia; el cliente controla el ritmo |
| **Suscripción mensual** | valor continuo, producto/servicio recurrente | hay que demostrar valor cada mes |
| **Por uso / resultado** | resultado medible y auditable | exige medición confiable y un criterio acordado |
| **Por asiento / usuario** | el valor escala con la adopción | si no hay adopción, el cliente cancela |
| **Base + éxito** | el cliente quiere compartir el riesgo | el flujo de caja y la facturación se complican |

## 2.3 Los 3 niveles — nunca uno solo

Con **una única opción**, la decisión del cliente se vuelve binaria: "compro o no compro". Con tres, pasa a ser "cuál compro". Eso reduce la indecisión (ver JOLT en `references/03-sales-methodologies.md`).

| Nivel | Función | Cómo diseñarlo |
|---|---|---|
| **Esencial** | resuelve el dolor principal, sin extras | el mínimo que entrega el resultado prometido |
| **Recomendado** | **el que quieres vender** | márcalo como recomendado — la recomendación explícita reduce la indecisión |
| **Completo** | ancla superior | hace que el recomendado parezca razonable; no tiene que ser el más vendido |

**Error común:** poner la mejor relación calidad-precio en el nivel más barato. El nivel recomendado debe ser el de mayor margen **y** el de mejor resultado para el cliente — si esas dos cosas no coinciden, el diseño está mal.

## 2.4 Economía unitaria — obligatoria antes de presentar

Para **cada** nivel, calcula:

```
Costo directo de entrega  = horas × costo/hora + insumos + terceros
Margen bruto              = precio − costo directo
Margen %                  = margen bruto / precio
Punto de equilibrio       = costo fijo asignado / margen bruto por unidad
```

**Regla estricta:** un nivel con margen negativo o con un punto de equilibrio por encima de tu capacidad **no entra en la propuesta**. Sin este cálculo, estás vendiendo para perder dinero.

## 2.5 Garantía con matemática de exposición

Antes de prometer cualquier garantía:

```
Exposición = (probabilidad de activación) × (costo de cumplirla)
```

- Si `Exposición > margen del nivel` → **no ofrezcas esa garantía**, o restringe el disparador.
- Garantías defendibles: rehacer sin costo **dentro del alcance escrito** · devolver la diferencia según una métrica acordada y auditable · período de salida con aviso previo · servicios profesionales incluidos hasta el valor.
- **Nunca prometas un resultado que depende del cliente** (p. ej., "vas a facturar X").

Enmarca la garantía como **depósito de confianza** (§1.3), no como un descuento disfrazado.

## 2.6 Mecanismos de encuadre

| Mecanismo | Cómo aplicarlo | Precaución |
|---|---|---|
| **Anclaje** | muestra la alternativa más cara (incluido "no hacer nada" y el costo del problema) antes de tu precio | el ancla debe ser real y verificable |
| **Señuelo (decoy)** | el nivel completo existe para orientar la elección hacia el recomendado | no menosprecies el nivel completo; debe ser defendible |
| **Encuadre anual** | muestra el equivalente mensual **y** el descuento anual | deja claro qué incluye el plan anual |
| **Lanzamiento vs. escala** | precio de entrada menor con una contrapartida declarada (p. ej., feedback, caso de estudio) | una fecha de fin real, no inventada |
| **Precio histórico** | el cliente antiguo mantiene el precio cuando sube | **dilo en voz alta** — es un depósito de confianza |

## 2.7 Lista de revisión de precio

- [ ] ¿La oferta tiene los seis elementos de §2.1?
- [ ] ¿El modelo elegido está declarado y justificado?
- [ ] ¿Hay tres niveles, con el recomendado marcado?
- [ ] ¿Se calculó la economía unitaria de cada nivel?
- [ ] ¿La garantía (si la hay) pasó por la matemática de exposición?
- [ ] ¿El precio está anclado a la alternativa del cliente, no a mi costo?
- [ ] ¿Existe un caso de estudio **autorizado** que respalde el valor?
- [ ] Si el cliente dice "está caro", ¿sé qué número suyo falta? (ver §4.3 de `references/04-outbound-and-objections.md`)
